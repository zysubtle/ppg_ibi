# 07_REVIEW_PROTOCOL.md

## 1. 默认审查输出格式

后续所有 Codex 输出审查，默认使用“决策卡”。

```text
【结论】
通过 / 不通过 / 需要我决策

【阻塞问题】
最多 3 条

【非阻塞问题】
最多 3 条，可选

【需要我决策】
无 / 有：xxx

【下一步】
我应该做什么
```

## 2. 问题分级

| 等级 | 含义 | 是否打扰 Owner |
|---|---|---|
| S0 | 必须 Owner 决策，例如 API 改变、算法策略改变、资源约束冲突 | 是 |
| S1 | 阻塞实现，但 Architect 可给 Codex 修复任务 | 通常否 |
| S2 | 技术风险，记录但不阻塞当前里程碑 | 否 |
| S3 | 风格、注释、清理问题 | 否 |

## 3. 修复轮次规则

每个里程碑最多两轮 Codex 修复。

如果两轮仍未通过，Architect 必须重新拆分任务，而不是继续让 Owner 搬运小修 prompt。

## 4. Owner 工作量限制

默认每轮只给 Owner：

1. 结论；
2. 是否需要 Owner 决策；
3. 最多 5 个关键点；
4. 下一步 Owner 要做什么。

除非 Owner 明确要求展开，否则不输出长篇技术审查。
