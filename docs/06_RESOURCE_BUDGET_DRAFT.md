# 06_RESOURCE_BUDGET_DRAFT.md

状态：草案，待 M2 细化。

## 1. 已冻结资源约束

| 项目 | 约束 |
|---|---|
| 目标 MCU | Apollo3.5 |
| RAM | `<20KB` |
| 动态内存 | 禁止 |
| float | 允许 |
| 定点化 | 暂不要求 |

## 2. 资源设计原则

1. 优先使用流式处理，避免保存长窗口原始数据。
2. 如果必须使用窗口，应限制窗口长度并明确 RAM 占用。
3. 多通道 PPG 的中间变量应复用，避免每路保存过多历史。
4. 算法状态必须集中在 context 结构体中。
5. 禁止动态内存。
6. Host 验证工具可以不受 MCU RAM 限制，但算法核心必须受限。

## 3. 初步 RAM 预算方向

以下只是 M2 讨论基线，不是最终分配。

| 模块 | RAM 方向 | 状态 |
|---|---|---|
| 输入历史 / 环形缓冲 | 尽量小，必要时保存短窗口 | 待 M2 定义 |
| 预处理滤波状态 | 每通道少量状态变量 | 待 M2 定义 |
| SQI / 通道选择 | 每通道统计量 | 待 M2 定义 |
| 峰值 / 脉搏检测 | 少量候选点与状态 | 待 M2 定义 |
| 输出与调试 | 默认精简，可选 debug | 待 M2 定义 |

## 4. M2 必须输出

M2 结束时应给出：

1. 预计 context 总 RAM；
2. 各模块 RAM 粗分配；
3. 是否需要保存完整 5 秒 PPG 窗口；
4. 是否需要保存多路 PPG 历史；
5. 是否需要编译期宏控制 debug 输出。
