# 14_M2_ALGORITHM_SPEC.md

版本：v0.1  
状态：待 Owner 确认后冻结

## 1. 算法目标

从 4 路严格同步绿光 PPG 中实时检测脉搏间隔，逐搏输出 IBI。

算法不计算 HRV、RMSSD、压力、恢复分或其他应用层指标。

## 2. 总体处理流程

每输入一个样本，算法按以下逻辑处理：

1. 检查 `allow_measure`；
2. 检查时间戳连续性；
3. 更新状态机；
4. 对 4 路 PPG 做轻量级预处理；
5. 评估各通道信号质量；
6. 选择主通道和备份通道；
7. 在主通道上检测 beat 候选；
8. 用备份通道和质量规则确认候选；
9. 由相邻有效 beat timestamp 计算 IBI；
10. 计算置信度；
11. 若满足有效性条件，则 `valid=true` 并输出 IBI；否则 `valid=false`。

## 3. 预处理原则

M4 实现时，预处理应满足以下原则：

1. 适合 MCU，避免大窗口和动态内存；
2. 允许使用 `float`；
3. 以流式 IIR / 轻量统计为主；
4. 目标频段覆盖主要心率频率，默认方向为 0.5~4.0Hz；
5. 保留每通道独立滤波状态；
6. 不在 MCU 算法内保存长时间原始 PPG。

推荐方向：

- 每通道 DC 去除；
- 带限滤波或等价高通 + 低通组合；
- 维护短期幅度、噪声、平坦度和饱和相关统计。

## 4. 多通道策略

M2 冻结策略：**主通道选择为主，备份通道辅助确认**。

### 4.1 主通道选择

每个通道计算 SQI，选择 SQI 最高且超过最低质量门限的通道作为主通道。

主通道切换需要有迟滞，避免频繁跳变。

### 4.2 备份通道使用

备份通道不强制参与每次 IBI 计算，但可用于：

1. 当主通道候选峰不确定时进行确认；
2. 当主通道质量下降时切换；
3. 降低单通道伪峰导致的误报。

### 4.3 不采用复杂融合作为 M4 必选项

M4 第一版不要求实现复杂的四通道加权融合、ICA、PCA 或自适应滤波。

原因：

1. RAM 预算 `<20KB`；
2. 输入只有 PPG，无 ACC 参与本项目；
3. 运动状态由外部门控；
4. 第一版重点是可测、可验、可迭代。

## 5. Beat 检测原则

M4 实现 beat 检测时，应满足：

1. 基于过滤后的主通道波形；
2. 检测局部峰值或等价的脉搏特征点；
3. 至少有最小 refractory 保护，避免同一搏重复检测；
4. IBI 候选必须位于 300~2000ms；
5. 第一个有效 beat 只建立参考点，不输出 IBI；
6. 从第二个有效 beat 开始，才可能输出 IBI；
7. 前 5 秒暖机或重新获取阶段不输出 IBI；
8. 质量不足、丢点严重或运动禁止时不输出 IBI。

## 6. IBI 有效性条件

一个 IBI 输出必须同时满足：

1. 当前状态为 `TRACK`；
2. `allow_measure=true`；
3. 当前不处于 warmup；
4. 当前 beat 候选有效；
5. 当前 IBI 在 300~2000ms；
6. 当前主通道 SQI 达到最低门限；
7. 严重丢点标志未触发；
8. 置信度达到有效门限。

## 7. 输出延迟

由于峰值确认通常需要观察峰值后的少量样本，算法允许存在小的输出延迟。

M2 不冻结具体延迟，但 M4/M5 应报告：

1. beat 时间戳定义方式；
2. IBI 输出相对真实峰值的延迟；
3. ECG 验证时采用的对齐方式。

## 8. 不做事项

本项目当前不做：

1. HRV / RMSSD 计算；
2. 运动识别；
3. ACC 运动伪迹消除；
4. 深度学习模型；
5. 复杂四通道融合；
6. 长窗口离线优化；
7. 动态内存分配；
8. 定点化优化。
