## 1. 总约束

| 项目 | 约束 |
|---|---|
| MCU | Apollo3.5 |
| RAM | `<20KB` |
| 动态内存 | 禁止 |
| float | 允许 |
| 定点化 | 暂不要求 |
| 输入 | 4 路 PPG，50Hz，`int32_t` |

## 2. RAM 预算方向

M2 建议将算法 context 目标控制在 `<8KB`，为后续调试、系统栈和上层模块留余量。

参考分配：

| 模块 | 预算方向 |
|---|---:|
| 配置与状态 | < 512B |
| 4 路滤波器状态 | < 1KB |
| 每通道滚动统计 / SQI | < 2KB |
| peak / beat tracker | < 1KB |
| 小型环形缓存 | < 2KB |
| debug / 计数器 | < 1KB |
| 余量 | > 2KB |

说明：

1. 不允许保存长时间原始 PPG；
2. 不建议保存 5 秒 × 4 通道完整 raw 窗口作为默认实现；
3. 如果 M4 需要短窗口，应优先保存过滤后主通道或统计量；
4. host 验证工具不受 MCU RAM 限制，但不得污染 MCU 核心接口。

## 3. CPU 预算方向

50Hz 下每秒只处理 50 个样本，每个样本 4 通道。

M2 不冻结具体周期数，但要求：

1. 单样本处理复杂度为 O(通道数) 或近似常数；
2. 不使用 FFT、矩阵分解或长窗口卷积作为 MCU 必选路径；
3. M4 需要避免在每个样本上反复扫描大窗口；
4. host 验证工具可以使用更复杂统计，但 MCU 算法不依赖。

## 4. Flash 预算方向

M2 不冻结 Flash 数值。

建议：

1. 不引入第三方 DSP 库作为必要依赖；
2. 若未来使用 CMSIS-DSP，应作为可选优化，不作为当前第一版要求；
3. 参数表和调试字符串应可裁剪。

## 5. 实现风格

1. C99；
2. 无动态内存；
3. 无文件 IO；
4. 无 printf 依赖；
5. 无系统线程依赖；
6. 接口可由上层每 20ms 调用一次；
7. 单元测试可在 host 环境运行。
