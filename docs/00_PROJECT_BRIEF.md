# 00_PROJECT_BRIEF.md

版本：v0.1  
状态：M0 已确认，M1 项目包生成中

## 1. 项目基本信息

项目名称：`ppg_ibi`

项目目标：在 Apollo3.5 MCU 上，基于 4 路严格同步的绿光 PPG 信号，实时计算逐搏 IBI。

应用用途：IBI 用于上层 HRV / RMSSD 等应用层指标计算。

## 2. 明确边界

本项目只负责：

1. 接收逐点 PPG 输入；
2. 根据 PPG 信号检测有效心搏；
3. 输出有效逐搏 IBI；
4. 输出置信度、状态、有效标志；
5. 根据外部运动标志暂停或重新获取。

本项目不负责：

1. 计算 HRV；
2. 计算 RMSSD；
3. 计算压力、恢复、睡眠等应用层指标；
4. 识别运动类型；
5. 输出运动时的 IBI。

## 3. 输入条件

| 项目 | 内容 |
|---|---|
| 输入信号 | PPG |
| 通道数 | 4 路 |
| 光源 | 绿光 |
| 同步性 | 4 路严格同步 |
| 采样率 | 50Hz |
| 数据类型 | `int32_t` |
| 时间戳 | 有 |
| 数据异常 | 可能丢点；暂不考虑乱序、重复或长时间中断 |
| 运动状态 | 由外部运动标志传入 |

## 4. 运行方式

算法逐点输入。

每次输入一个采样点，包含同一时刻的 4 路 PPG 数据。算法处理该采样点后，调用方检查是否产生新的有效 IBI 输出。

## 5. 输出要求

| 输出字段 | 说明 |
|---|---|
| IBI 数值 | 逐搏 IBI，默认单位待 M2 冻结，当前默认假设为 ms |
| confidence | 当前 IBI 置信度 |
| state | 算法内部状态 |
| valid flag | 当前是否有有效 IBI 输出 |

输出方式：逐搏输出。只有检测到有效心搏并形成有效 IBI 时，才输出有效 IBI。

无效处理：无效时不输出有效 IBI。

运动打断处理：外部运动标志提示不允许测量时，暂停 IBI 计算；被运动打断后重新获取。

启动等待：允许前 5 秒不输出。

## 6. 平台和资源约束

| 项目 | 约束 |
|---|---|
| MCU | Apollo3.5 |
| 浮点 | 允许使用 `float` |
| 定点化 | 暂不要求 |
| 动态内存 | 禁止 `malloc/free` |
| RAM | `< 20KB` |
| 仓库状态 | 空仓库，从零开始 |

## 7. 验证资源与验收方向

已有 ECG 真值，可用于验证 PPG-IBI 准确性。

验收指标方向：

1. IBI 准确率；
2. IBI 误差范围；
3. 漏检率；
4. 误报率；
5. RAM 占用。

具体数值阈值暂不在 M1 冻结，后续 M2 / 验证规格阶段定义。

## 8. 待确认默认假设

以下内容还不是最终事实，后续 M2 需要冻结：

1. 时间戳字段默认使用 `uint32_t timestamp_ms`。
2. 运动标志默认设计为类似 `allow_measure` 的布尔输入。
3. 丢点通过时间戳间隔检测。
4. 轻微丢点可标记当前质量下降，严重丢点触发重新获取。
5. IBI 单位默认使用 ms。
6. 算法状态初步可包含：`INIT / ACQUIRE / TRACK / HOLD / REACQUIRE`。
